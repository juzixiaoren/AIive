## 1. 本轮做了什么

### 1.1 阶段一：建立真实基线

- 发现并修复**测试环境失真**：`.venv` 原为 uv 的非可编辑复制安装，`import aiive` 解析到
  `.venv/Lib/site-packages/aiive`（陈旧副本），此前所有测试跑的都不是工作区代码。已改为可编辑安装，
  现解析到 `backend/aiive`。这是本轮最重要的发现——不做这一步，后续任何「重构通过」都不可信。
- 用 AST 扫描 backend/aiive（约 203 个模块）构建依赖图并求强连通分量（SCC），结论见 `docs/CODE_MAP.md` §10。
- 记录基线：修复前同环境 8 failed / 849 passed / 676s（失败均为重构前既有）。

### 1.2 阶段二：拆 builtin_tools.py

`backend/aiive/tools/builtin_tools.py` 从 1360 行降到 397 行，只保留三样东西：

1. **共享机制（单一实现）**：`_build_safety` / `_db_handler`（会话开-提交-回滚-关闭 + RunContext 注入）/ `_require_ctx`；
2. **统一注册入口**：`register_builtin_tools(registry)`，36 个工具的元组表原样保留；
3. **兼容 re-export**：把域模块的 `_handle_*` 重新导出，历史调用方（测试、registry、selfdev）无需改动。

### 1.3 阶段三：重构 agent_graph.py

从同步与流式两条路径中提取 4 个共享方法（不改变对外接口与 LangGraph 语义）：

| 方法 | 职责 |
| --- | --- |
| `_prepare_execution` | 组装上下文、建 registry/tools、编译图（同步直接调用；流式把 DB 调用包进 asyncio.to_thread） |
| `_extract_reply` | 从消息序列抽取最终回复（优先无 tool_calls 的 AIMessage） |
| `_classify_memory_signal` | 记忆信号分类 + 策略裁决（同步直调；流式走 to_thread） |
| `_assemble_agent_result` | 工具记录归一、快照回填、结果 DTO 组装 |

保留的**合理差异**：`compiled.invoke` 与 `compiled.astream_events(version="v2")` 的事件解析、
`_StreamToolCallMatcher` 的增量工具调用拼装、流式 token 累积——这些语义不同，未强行合并。

### 1.4 阶段四：死代码与重复实现

无法验证 PG 的锁与隔离级别语义，因此本轮**不做拆分**，只记录建议（见 §3）。

## 5. 后续开发必要信息

### 5.1 加/改工具时改哪里

1. handler 写在对应领域模块 `backend/aiive/tools/builtin_<domain>.py`；
2. 需要 DB 会话的 handler 加 `@_db_handler`（从 `aiive.tools.builtin_tools` 导入）；
3. side-effect 工具在函数体内用 `_require_ctx(ctx, "tool_name")` 快速失败；
4. 工具元组统一加在 `builtin_tools.py::register_builtin_tools` 的表里（名称/Schema/风险等级/是否写外部世界/是否可删除）；
5. **不要在域模块里新建 `SessionLocal`**：会话工厂必须留在 `builtin_tools` 命名空间，
   因为 tests 与 `tests/support.py` 会 monkeypatch `aiive.tools.builtin_tools.SessionLocal` 把会话重定向到测试库。

### 5.2 改 AgentGraph 时注意

- 同步与流式共用 `_prepare_execution` / `_extract_reply` / `_classify_memory_signal` / `_assemble_agent_result`；
  新增共享逻辑请优先加进这四个方法，而不是两条路径各写一遍。
- **trace 必须由调用方创建后传入** `_prepare_execution`，否则 `trace_id` 为空时会出现两条链路。
- 流式事件解析、`_StreamToolCallMatcher`、token 累积属于流式特有语义，不要为「合并」而合并。

### 5.3 测试怎么写（三层结构，必读）

```
tests/
├── conftest.py            根：注入 SQLite 地址/关向量、进程级库建表、统一结果输出
├── support.py             SessionLocal 分发器（先于业务模块导入安装）
├── unit/backend/          532 项：纯逻辑不建库；需要 DB 时显式请求 db_session
├── integration/           315 项：真实组件组合；用 db 夹具（进程级共享库）
│   └── backend/           含 _util.py、fixtures/
└── flow/                  10 项：Turn 执行、提醒闭环
```

- **单元/流程层**：需要数据库就写 `def test_x(db_session):`；不需要就不写（零成本，不建库）。
  `db_session` 会把隔离会话注册给分发器，被测代码内部自开的 `SessionLocal()` 也落到该用例临时库。
- **集成层**：用 `db` 夹具，不要用 `db_session`（集成层需要多会话读同一物理库）。
  `db` 夹具已是「会话级建表 + 用例级清空数据」，比每用例重建表快一个数量级。
- **不请求 `db_session` 的用例**会落到进程级库（已建表），适合需要生产代码自开会话提交的场景。
- 层级筛选用目录路径：`pytest tests/unit`；`-m unit` 在 pytest 9 下不生效（marker 过滤先于 conftest 打标）。
- 禁止新增需要 API Key / 外网 / 第三方额度的测试；用 `monkeypatch` 替换传输层，保留请求构造与错误归一化。

### 5.5 已知陷阱

1. **惰性循环依赖**：域模块 → `builtin_tools`（取共享机制）与 `builtin_tools` → 域模块（re-export）互为环，
   但共享符号先于 re-export 定义，`import aiive.tools.builtin_tools` 先行时安全；若某个域模块先被导入会 ImportError。
   新增域模块时保持 `from aiive.tools.builtin_tools import _db_handler, _require_ctx` 这一形式即可。
2. **`create_all` 必须导入全部模型模块**，否则缺表（历史 bug：`forget_tombstones`）。
3. **测试环境是 SQLite**：无 pgvector（向量召回强制关闭）、FK 需 `PRAGMA foreign_keys=ON`；
   涉及 PG 特有语义的改动不能只靠本环境验证。
4. **不要还原 `backend/tests/`、`backend/conftest.py`、`backend/pytest.ini`**：它们已被有意删除，
   还原会导致同一批用例重复收集。

## 6. 关键决策记录

| 决策 | 理由 |
| --- | --- |
| 共享机制留在 `builtin_tools.py`，不下沉到 `_shared.py` | 测试与 `tests/support.py` monkeypatch `builtin_tools.SessionLocal`；下沉会让该属性消失（曾实测 6 errors，已回退） |
| 域模块用 re-export 而非改调用方 | 保持 `aiive.tools.builtin_tools._handle_*` 历史接口，测试与 selfdev 无需改动 |
| 不拆 `memory_write_service.py` | 事务边界与 PG 语义无法在本环境证伪，拆分风险大于收益 |
| 集成层改「建表一次 + 清数据」 | DDL 是每用例最贵开销；隔离语义（每用例干净数据）不变 |
| 用 `getattr(assembled_ctx, "tool_registry", None)` | 该字段默认值本就是 None，「缺失」与「显式 None」语义一致，真实调用方行为不变 |
