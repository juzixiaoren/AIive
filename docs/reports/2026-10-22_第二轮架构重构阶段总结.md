## 1. 本轮做了什么

### 1.1 CI 接入 ruff（第一轮 §4 第 1 项）

`.github/workflows/ci.yml` 新增 `ruff` job：

```yaml
- name: 运行 ruff
  run: ruff check backend/aiive --select F,E9
```

只把「未定义名 / 语法错误」这类真实缺陷设为门禁，风格项（UP037、B023、BLE001 等）不阻断，
与 `docs/CODE_MAP.md` §10.5 的本地基线口径一致。

### 1.2 顺序依赖防线（第一轮 §4 第 5 项）

新增 `scripts/check_single_file_tests.sh`：

- 对 `tests/` 下每个 `test_*.py` 单独起一个 pytest 进程；
- 根 `conftest.py` 用 PID 命名 SQLite 库，因此多进程并发互不干扰；
- 任一文件单独运行失败即退出非零，并打印该文件日志尾部；
- 支持 `PYTHON_BIN` / `JOBS` / `PYTEST_TARGETS` 环境变量，本地与 CI 共用同一脚本。

CI 新增 `single-file` job 调用该脚本（`JOBS=2`）。此前只有 `test_v2_recall` 与
`test_tool_calling_runtime` 两个抽样点，现在覆盖全部 91 个文件。

### 1.3 basedpyright 告警清零（第一轮 §4 第 2 项）

第一轮遗留 66 条 warning，主体是域模块 re-export 私有 `_handle_*` 触发的
`reportPrivateUsage` / `reportUnusedFunction`。处理方式：

| 改动 | 范围 | 兼容性 |
| --- | --- | --- |
| handler 改公开名 `handle_*` | 10 个 `builtin_*.py` 领域模块 | `builtin_tools` 用 `handle_x as _handle_x` re-export，tests / selfdev 的 `_handle_*` 引用不变 |
| 共享机制改公开名 `db_handler` / `require_ctx` | `builtin_tools.py` + 6 个使用方 | `SessionLocal` 仍与 `db_handler` 同模块，monkeypatch 契约不变 |
| 删除多余 `# pyright: ignore` | mcp 2 个文件、task_runtime/repository.py | 这 8 条已被 pyright 判为 unnecessary，删除后仍 0 error |
| `func.max` 空表判断类型收窄 | `retrieval/retrieval_index.py::next_index_version` | 运行期语义不变（空表仍返回版本 1），仅把 `int` 误判改为 `int \| None` |

没有关闭或放宽任何 pyright 规则，`pyproject.toml` 的 `[tool.basedpyright]` 未改动。

## 3. 关键决策

| 决策 | 理由 |
| --- | --- |
| 域模块用公开名、`builtin_tools` 保留私有别名 | 消除跨模块私有引用，同时不破坏 tests 对 `_handle_*` 的既有引用（测试归用户维护，本轮零测试改动） |
| 单文件防线做成脚本而不是内联 CI 命令 | 本地与 CI 用同一份逻辑，失败时能直接复现；也避免 YAML 里堆 bash |
| ruff 只开 `F,E9` 门禁 | 风格项在第一轮已记录为「既有」，现在设为门禁会让历史风格问题阻塞无关改动 |
| 修 `func.max` 的恒真比较而不是 ignore | 该处 `row[0]` 运行期确实可能为 NULL，按 `int \| None` 收窄比压告警更准确 |

## 4. 未做与下一步

1. **CI 尚未在真实 GitHub Actions 上跑过**：本轮是本地等价验证（同命令、同 Python 3.12 + SQLite）。
   推送后需确认 `single-file` job 的耗时与稳定性。
2. **PG 语义回归仍未覆盖**（第一轮 §4 第 4 项）：`memory_write_service.py` 的事务/锁/幂等需要真实
   PostgreSQL；本机无 PG 环境，且测试文件归用户维护，本轮未新增 PG 用例。
3. **3 个惰性循环依赖未拆**（第一轮 §4 第 3 项，CODE_MAP §10.3）：需侵入 control/worker/registry 契约。
4. 单文件 job 使 CI 时长增加约 6 分钟；若后续变慢，可提高 `JOBS` 或改为按层抽样。

## 5. 后续开发必要信息（增量）

- **新增 handler 的命名**：领域模块写 `def handle_xxx(...)`；在 `builtin_tools.py` 的导入块里写
  `from aiive.tools.builtin_<domain> import handle_xxx as _handle_xxx`，注册表继续用 `_handle_xxx`。
  不要反过来（在域模块写私有名）——那会重新引入 reportPrivateUsage。
- **需要 DB 的 handler**：装饰器是 `@db_handler`（公开名），从 `aiive.tools.builtin_tools` 导入；
  side-effect 工具用 `require_ctx(ctx, "tool_name")`。
- **提交前自查**：
  ```
  ruff check backend/aiive --select F,E9
  basedpyright
  python -m pytest tests/unit tests/flow      # 日常
  bash scripts/check_single_file_tests.sh     # 改动涉及夹具 / 模块级状态时
  ```
- **单文件脚本注意**：它按 `find tests -name 'test_*.py'` 取文件，新增测试目录会自动纳入；
  日志写到临时目录并在退出时清理，不会污染工作区。
