# P0 — 前置验证（PoC）

> **目标**：在正式编码前，验证 CodeBuddy CLI 的核心能力，确认技术路线可行  
> **预计耗时**：0.5 - 1 天  
> **优先级**：🔴 最高 — 此阶段不通过则需切换技术方案

---

## 1. 验证目标

在正式进入 P1 编码之前，必须确认以下核心依赖的可行性：

| # | 验证项 | 重要度 | 说明 |
|---|---|---|---|
| 1 | CodeBuddy CLI 安装与配置 | 🔴 必须 | `@tencent-ai/codebuddy-code` 能否正常安装 |
| 2 | 程序化调用（非交互模式） | 🔴 必须 | `codebuddy -p "prompt"` 能否正常返回结果 |
| 3 | 自定义工具注册 | 🔴 必须 | 能否注册自定义的 `file_read` 等工具并被 LLM 调用 |
| 4 | 流式输出 | 🔴 必须 | 能否获取流式的 token 输出（用于 SSE 转发） |
| 5 | Hook 系统 | 🟡 重要 | `PreToolUse` / `PostToolUse` 是否可用（用于安全拦截） |
| 6 | 模型选择 | 🟡 重要 | CodeBuddy 内部模型切换是否正常 |
| 7 | Docker 环境运行 | 🟡 重要 | CodeBuddy CLI 能否在 Docker 容器中正常运行 |

### 2.2 验证 1：基础程序化调用

```typescript
// poc/test-basic.ts
// 目标：验证 CodeBuddy CLI 能否以程序化方式调用并返回结果

import { execFile } from 'child_process';
import { promisify } from 'util';

const exec = promisify(execFile);

async function testBasicCall() {
  console.log('=== 验证 1: 基础程序化调用 ===');
  
  try {
    // 方式 A: CLI 直接调用
    const { stdout } = await exec('npx', [
      'codebuddy', '-p', '请回复 "Hello AIive"，不要说其他内容'
    ], { timeout: 30000 });
    
    console.log('✅ CLI 调用成功');
    console.log('输出:', stdout.trim());
    return { success: true, method: 'cli', output: stdout.trim() };
  } catch (error: any) {
    console.log('❌ CLI 调用失败:', error.message);
    
    // 方式 B: 尝试 API 方式
    try {
      // 如果 CLI 不支持程序化调用，尝试直接使用 SDK
      const sdk = await import('@tencent-ai/codebuddy-code');
      console.log('SDK 导出:', Object.keys(sdk));
      return { success: false, method: 'cli-failed', sdkExports: Object.keys(sdk) };
    } catch (sdkError: any) {
      console.log('❌ SDK 导入也失败:', sdkError.message);
      return { success: false, method: 'both-failed', error: error.message };
    }
  }
}

testBasicCall().then(result => {
  console.log('\n=== 结果 ===');
  console.log(JSON.stringify(result, null, 2));
});
```

### 2.4 验证 3：流式输出

```typescript
// poc/test-stream.ts
// 目标：验证能否获取流式 token 输出

async function testStreamOutput() {
  console.log('=== 验证 3: 流式输出 ===');
  
  // 方式 A: CLI stdout 流式读取
  const { spawn } = await import('child_process');
  
  const child = spawn('npx', [
    'codebuddy', '-p', '请写一首关于 AI 的短诗，4 行即可'
  ]);

  let fullOutput = '';
  let chunkCount = 0;

  child.stdout.on('data', (chunk: Buffer) => {
    const text = chunk.toString();
    chunkCount++;
    fullOutput += text;
    process.stdout.write(`[chunk ${chunkCount}] ${text}`);
  });

  child.stderr.on('data', (chunk: Buffer) => {
    console.error('[stderr]', chunk.toString());
  });

  return new Promise((resolve) => {
    child.on('close', (code) => {
      console.log(`\n\n=== 流式输出结果 ===`);
      console.log(`退出码: ${code}`);
      console.log(`总 chunk 数: ${chunkCount}`);
      console.log(`是否流式: ${chunkCount > 1 ? '✅ 是' : '❌ 否（一次性输出）'}`);
      resolve({
        success: code === 0,
        isStreaming: chunkCount > 1,
        chunkCount,
        outputLength: fullOutput.length,
      });
    });
  });
}

testStreamOutput();
```

## 3. Fallback 方案

如果 CodeBuddy CLI 的 PoC 验证失败，按以下优先级切换：

### 方案 A：直接调用 LLM API + 自建工具循环

```
优点: 完全可控，无第三方依赖
缺点: 需要自己实现 Agent 循环（工具调用 → 结果注入 → 继续推理）
工作量: +2-3 天
实现: 
  - 直接调用 Anthropic Claude API / OpenAI API
  - 自建 tool_use → tool_result 循环
  - 自建流式输出转发
```

### 方案 B：Vercel AI SDK

```
优点: 成熟的 Agent 框架，TypeScript 原生
缺点: 需要自行管理 API Key 路由
工作量: +1-2 天
实现:
  - @ai-sdk/anthropic 或 @ai-sdk/openai
  - 内置工具调用循环
  - 内置流式输出
```

### 方案 C：Claude Agent SDK

```
优点: Anthropic 官方 Agent SDK
缺点: 生态较新，可能不够稳定
工作量: +1-2 天
实现:
  - @anthropic-ai/claude-agent-sdk
  - 原生支持工具调用和 Agent 循环
```

> **关键设计**：无论使用哪个方案，核心的 Agent 循环都封装在 `src/core/agent.ts` 的 **SDK Adapter** 层中。四大元工具、文件系统、记忆系统等上层逻辑完全不受影响。

| # | 验证项 | 通过标准 | 状态 |

## 6. 与后续 Phase 的关系

```
P0 验证结果 → 决定 P1 的 Agent Core 实现方式
                │
                ├─ CodeBuddy CLI 可用 → 直接使用，P1 按原计划执行
                │
                ├─ 部分可用 → 记录限制，P1 中绕过不可用的功能
                │
                └─ 不可用 → 切换 Fallback 方案
                            │
                            └─ 修改 P1 的 src/core/agent.ts 实现
                               其余部分（工具、文件系统、前端）不变
```

> **核心保障**：SDK Adapter 模式确保 P0 的任何结果都不会影响 P1-P3 的整体架构。
