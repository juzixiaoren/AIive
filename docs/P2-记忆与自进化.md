### 2.2 短期记忆 — JSONL + 内存索引

```jsonl
{"id":"mem-001","ts":"2026-04-16T10:30:00Z","type":"session_compact","tags":["react","bug"],"summary":"用户遇到 React useEffect 闪烁问题","ttl":7}
{"id":"mem-002","ts":"2026-04-16T14:00:00Z","type":"fact","tags":["user"],"summary":"用户偏好 TypeScript 严格模式","ttl":30}
```

**ShortTermMemory 类核心方法：**

```typescript
class ShortTermMemory {
  private tagIndex = new Map<string, MemoryEntry[]>();
  private idIndex = new Map<string, MemoryEntry>();

  async buildIndex(): Promise<void>;           // 启动时从 JSONL 构建索引
  findByTag(tag: string): MemoryEntry[];       // O(1) 按标签查找
  search(keyword: string): MemoryEntry[];      // 遍历 summary 搜索
  async append(entry: MemoryEntry): Promise<void>;  // 追加新记忆
  async gc(): Promise<number>;                 // 原子写入清理过期记忆
}
```

**GC 原子写入**：使用 write-then-rename 模式，先写 `.tmp` 再 `rename`，防崩溃丢数据。

## 3. 上下文压缩机制

### 3.1 三级预警

```
🟢 正常:     总 token < 上下文窗口 × 70%
🟡 黄色预警:  总 token > 上下文窗口 × 80%
   → 注入提醒: 「建议调用 memory_compress 压缩历史」
🚨 自动压缩:  总 token > 上下文窗口 × 93%
   → 自动触发压缩（不等 LLM 主动调用）
   → 熔断机制：连续 3 次失败后停止自动重试
🔴 硬限制:    总 token > 上下文窗口 × 97%
   → 强制截断最早的消息
```

### 3.2 memory_compress 工具

```typescript
interface MemoryCompressInput {
  scope: 'all' | 'before_last_n';
  keepLastN?: number;    // 默认 5
  summary?: string;      // LLM 可提供自己的摘要
}

// 流程:
// 1. 确定压缩范围（all: 仅保留最后 1 条; before_last_n: 保留最近 N 条）
// 2. 生成摘要（LLM 提供 or 自动生成）
// 3. 写入 memories/short-term/session.jsonl
// 4. 从 Session 移除已压缩消息
// 5. 在保留消息前插入压缩摘要
// 6. 更新 token 统计
```

## 4. 自进化机制

### 4.1 三种进化模式

#### Mode A: 调整行为偏好

```
触发: 「以后输出用表格格式」
动作: 修改 change_system.md，追加偏好规则
效果: 后续回复自动使用表格
```

#### Mode B: 获取新技能

```
触发: 「我已经连续 3 次手动执行同一个流程」
动作:
  1. 创建 skills/xxx/SKILL.md
  2. 创建 skills/xxx/impl.md
  3. 更新 memory.md 注册新技能
  4. 记录到 .evolution-log/
效果: 下次直接调用该技能
```

#### Mode C: 知识沉淀

```
触发: 「React 19 的 useOptimistic 有个 breaking change」
动作:
  1. 写入 knowledges/react/use-optimistic-v19.md
  2. 追加 memories/long-term/by-event/react-knowledge.md
  3. 更新 memory.md
  4. 记录到 .evolution-log/
效果: 未来 React 相关对话能利用此知识
```

### 4.2 进化安全约束

```
1. 【备份原则】修改前必须备份到 .evolution-log/backups/
2. 【事务原子性】多文件操作作为原子事务，任一步失败全部回滚
3. 【回滚窗口】24 小时内可用「撤销上次进化」恢复
4. 【审计追踪】每次进化写入 .evolution-log/（事务 ID、操作列表、原因、diff）
5. 【禁区】不能修改 soul.md / system.md / 元工具文件 / 历史日志
6. 【审批制】高风险操作需用户确认（删除 skill、大幅修改 change_system.md）
7. 【并发控制】进化事务需获取 .evolution-log/.lock 文件锁
```

### 4.3 进化日志格式

```markdown
---
id: evo-20260416-001
timestamp: 2026-04-16T14:30:00Z
transaction:
  - action: modify
    target: change_system.md
    backup: .evolution-log/backups/change_system.md.bak.20260416T143000
  - action: modify
    target: memory.md
    backup: .evolution-log/backups/memory.md.bak.20260416T143000
reason: 观察到用户偏好表格输出
confidence: high
approved: auto
rollback_available: true
---
```

## 6. 错误重试与模型降级

### 6.1 RetryPolicy

```typescript
const DEFAULT_RETRY_POLICY = {
  maxRetries: 3,
  baseDelayMs: 1000,
  maxDelayMs: 30000,
  backoffMultiplier: 2,
  retryableErrors: ['NETWORK_ERROR', 'TIMEOUT', 'RATE_LIMITED', 'SERVICE_UNAVAILABLE'],
};
```

### 6.2 模型降级链

```
主模型 → 备用模型 1 → 备用模型 2
  ↑                              │
  └── 定时探测（每 5 分钟） ←────┘
```

- 连续 2 次失败触发降级
- 降级后每 5 分钟探测主模型是否恢复
- 恢复后自动升级回主模型

### 6.3 SSE 断线恢复

```
├── EventSource 内置自动重连（3 秒）
├── 服务端附带递增 Event ID
├── 重连时发送 Last-Event-ID
└── 服务端从断点继续推送
```

## 9. 验收标准

| 验收项 | 标准 |
|---|---|
| **记忆写入** | 说「记住我喜欢 TypeScript」→ session.jsonl 有新记录 |
| **记忆召回** | 下次对话中 Agent 自觉提及 TypeScript 偏好 |
| **自进化** | 说「把输出风格改为幽默」→ change_system.md 被修改 → 后续回复变幽默 |
| **进化回滚** | 说「撤销上次进化」→ change_system.md 恢复原状 |
| **上下文压缩** | 长对话后触发黄色预警 → Agent 调用 memory_compress → token 下降 |
| **熔断机制** | 连续 3 次压缩失败 → 停止自动重试 |
| **模型降级** | 主模型不可用 → 自动切换备用模型 → 主模型恢复后自动切回 |
| **Skills 加载** | skills/ 下新增技能 → Agent 能在目录列表中看到 |
| **file_patch** | Agent 能用 search-and-replace 修改文件特定部分 |
| **编年体** | 当天的操作记录出现在 by-date/YYYY-MM-DD.md |
| **纪传体** | 项目相关记忆出现在 by-event/project-aiive.md |
