# P1 — 核心引擎（MVP）

> **目标**：能在 Web 中与 Agent 对话，Agent 能读写文件、执行命令、发请求

### 3.2 单次请求处理流程

```
用户发送: "帮我分析一下 src/utils/data.ts 这个文件"

Step 1: 接收消息
  POST /api/chat { message: "帮我分析一下 src/utils/data.ts" }
  → 返回 { sessionId: "xxx" }

Step 2: 建立 SSE 连接
  GET /api/chat/stream/:sessionId

Step 3: 构建 Prompt（Prompt Assembly — 按需加载）
  ├─ [必须] 读取 system.md → 注入固定系统提示词
  ├─ [必须] 读取 soul.md → 注入人格约束
  ├─ [必须] 读取 change_system.md → 注入动态偏好
  ├─ [必须] 读取 agent.md → 注入身份信息
  ├─ [必须] 读取 memory.md 概览 → 注入记忆目录索引
  ├─ [必须] 扫描 skills/ 目录 → 仅注入技能名称列表
  └─ [按需] 具体内容由 Agent 通过 file_read 自行获取

Step 4: 调用 CodeBuddy CLI（程序化调用）
  Agent 内部循环: LLM → 工具调用 → 结果注入 → 继续推理

Step 5: SSE 流式返回给用户（实时打字机效果）

Step 6: 后台异步任务
  ├─ 将本次对话摘要写入 memories/short-term/session.jsonl
  └─ 更新 memory.md 概览
```

## 4. 四大元工具详细规格

### 4.1 总览

| 工具名 | 功能 | 安全机制 |
|---|---|---|
| `file_read` | 读取文件内容 | symlink 检测 + 编码检测 + 100KB 截断 |
| `file_write` | 创建/覆盖/追加文件 | 受保护目录 + 受保护文件（完整路径匹配） |
| `shell_exec` | 执行 Shell 命令 | 双模式（safe/shell）+ 危险拦截 + 超时 |
| `http_request` | HTTP 请求 | URL 协议验证 + 5MB 响应限制 |

### 4.2 ToolContext 接口

```typescript
interface ToolContext {
  agentRoot: string;
  currentSession: Session;
  evolutionLog: EvolutionLogger;
  shortTermMemory: ShortTermMemory;
  logger: Logger;
  modelFallback: ModelFallback;
}
```

### 4.3 file_read

```typescript
interface FileReadInput {
  path: string;
  offset?: number;    // 起始行（1-based）
  limit?: number;     // 最大行数
  encoding?: 'utf-8' | 'latin-1';
}

// 关键安全逻辑:
// 1. realpathSync 解析真实路径，防 symlink 攻击
// 2. 路径必须在 agentRoot 内
// 3. 自动编码检测（UTF-8 BOM → UTF-8 → Latin-1 fallback）
// 4. 100KB 硬限制截断
```

### 4.4 file_write

```typescript
interface FileWriteInput {
  path: string;
  content: string;
  mode: 'overwrite' | 'create' | 'append';
  encoding?: 'utf-8' | 'latin-1';
}

// 受保护目录（正则匹配）:
// /System, /Library, /bin, /sbin, /etc, /dev, /proc
// /usr/bin, /usr/sbin, /var/log
// node_modules/, .git/

// 受保护文件（完整路径匹配，仅 agentRoot 下）:
// soul.md, system.md

// 进化相关文件（change_system.md, memory.md）修改时自动记录日志
```

### 4.5 shell_exec

```typescript
interface ShellExecInput {
  command: string;
  timeout?: number;   // 默认 30000ms
  cwd?: string;
  mode?: 'safe' | 'shell';  // 默认 'safe'
}

// safe 模式: execFile（不经过 shell，防注入，不支持管道/重定向）
// shell 模式: exec（支持管道/重定向，加强审计日志）

// 危险命令黑名单:
// rm -rf /, mkfs, dd, chmod 777, curl|bash, shutdown, reboot
// fork 炸弹, git push --force
```

### 4.6 http_request

```typescript
interface HttpRequestInput {
  url: string;
  method: 'GET' | 'POST' | 'PUT' | 'DELETE' | 'PATCH';
  headers?: Record<string, string>;
  body?: string;
  timeout?: number;    // 默认 15000ms
}

// 仅允许 http/https 协议
// 响应体限制 5MB，流式读取
// 超时最大 60s
```

### 4.8 Token 估算

```typescript
// utils/tokens.ts — 使用 @anthropic-ai/tokenizer 精确计算
import { countTokens } from '@anthropic-ai/tokenizer';

export function estimateTokens(text: string): number {
  return countTokens(text);
}

export function isOverBudget(texts: string[], budgetTokens: number) {
  const total = texts.reduce((sum, t) => sum + countTokens(t), 0);
  return { over: total > budgetTokens, total, remaining: budgetTokens - total };
}
```

## 6. Session 管理

### 6.1 Session 生命周期

```
创建 ──→ 活跃 ──→ 空闲 ──→ 关闭
                    ↑
                    └── P2 增加: 压缩状态
```

### 6.2 Session 数据结构

```typescript
interface Session {
  id: string;
  createdAt: string;
  lastActiveAt: string;
  status: 'active' | 'idle' | 'closed';
  messages: Message[];
  tokenUsage: {
    systemPrompt: number;
    conversationHistory: number;
    toolResults: number;
    total: number;
    limit: number;
  };
}

interface Message {
  role: 'user' | 'assistant' | 'system' | 'tool';
  content: string;
  timestamp: string;
  tokenCount: number;
  toolCalls?: ToolCallRecord[];
}
```

### 6.3 Session 持久化（P1 简化版）

```
P1 持久化策略:
├── 内存中维护活跃 Session
├── 每 5 条消息自动保存快照到 memories/short-term/active.json
├── Session 结束时写入 memories/short-term/session.jsonl
├── 服务重启后从 active.json 恢复
└── active.json 损坏时 fallback 到 session.jsonl
```

## 8. 安全控制

### 8.1 多层纵深防御

```
Layer 1: 路径安全
  ├── realpathSync 解析 symlink
  ├── 路径必须在 agentRoot 内
  └── 受保护目录正则匹配

Layer 2: 文件安全
  ├── soul.md / system.md 不可写（完整路径匹配）
  └── 进化文件修改自动记录日志

Layer 3: 命令安全
  ├── 危险命令黑名单
  ├── safe 模式 execFile（防注入）
  └── 超时保护（30s 默认，300s 上限）

Layer 4: 网络安全
  ├── 仅允许 http/https
  └── 响应体 5MB 限制
```

## 11. 验收标准

| 验收项 | 标准 |
|---|---|
| **基础对话** | 发送文本消息 → Agent 返回有意义的回复 |
| **工具调用** | 发送「读取 agent.md」→ Agent 调用 file_read → 返回文件内容 |
| **流式输出** | 全程 SSE 流式输出可见，打字机效果 |
| **工具状态** | 前端能看到工具调用的名称、参数、结果 |
| **安全拦截** | 尝试读取 /etc/passwd → 被拦截 |
| **Docker** | `docker compose up` 后服务正常运行 |
| **Session** | 服务重启后能恢复上一个 Session |
| **记忆写入** | 对话结束后 session.jsonl 有新记录 |

## 12. 风险与注意事项

```
⚠️ P1 关键风险:
1. CodeBuddy CLI 集成 — 依赖 P0 验证结果，准备 SDK Adapter 适配层
2. SSE 流式输出 — 确保 Hono 的 SSE 支持稳定
3. Docker 环境 — CodeBuddy CLI 在容器内的行为可能与本地不同

💡 P1 设计原则:
1. 先跑通再优化 — 不追求完美，先让 Agent 能对话
2. SDK Adapter 模式 — Agent Core 可替换，其余不变
3. 安全第一 — 四大元工具的安全检查不能省
4. Graceful Shutdown — 监听 SIGTERM，保存 Session 快照
```
