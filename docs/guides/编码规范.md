# AIive 编码规范

> 本文件是 AIive 交给编码 AI 实现时的硬约束。任何 `project_plan_vX.md` 都必须以本规范为上位约束。若阶段文件与本规范冲突，以本规范为准，除非用户明确修改。

---

## 1. 总原则

AIive 是单用户本地个人 Agent OS，不是普通聊天机器人。编码时必须服务于四条长期主线：

```text
1. 越来越懂用户：长期记忆、偏好、节奏、项目上下文、纠错样本。
2. 越来越会主动维护生活节奏：提醒、routine、condition watch、低打扰主动建议。
3. 越来越会维护自己的软件身体：trace、test、A/B slot、self-dev、rollback、maintenance。
4. 越来越会给自己加能力：tool registry、MCP discovery、MCP sandbox、capability lifecycle。
```

编码 AI 不得把 AIive 实现成一次性问答应用、普通 RAG 项目、普通 todo app 或普通 IDE 插件。

## 2. 技术选型锁定

### 2.1 后端

```text
语言：Python 3.12+
API 框架：FastAPI
数据校验：Pydantic v2
数据库：PostgreSQL 16+
ORM / SQL：SQLAlchemy 2.x
数据库迁移：Alembic
数据库驱动：psycopg 3
HTTP 客户端：httpx
配置：pydantic-settings + .env
测试：pytest
LLM：OpenAI-compatible Chat Completions 自研 client
后台任务：PostgreSQL outbox worker + Python worker loop
```

不允许自行替换为：

```text
Django
Flask
SQLite-only 架构
MongoDB
Redis/Celery/Kafka/RabbitMQ 作为早期任务队列
Next.js 全栈后端
Electron
复杂多用户认证系统
```

### 2.2 前端

```text
框架：React + Vite + TypeScript
请求状态：TanStack Query
路由：React Router 或 TanStack Router，确定后不得频繁切换
样式：CSS Modules 或 Tailwind，确定后不得频繁切换
主要入口：Chat Page
解释页面：Events、Context、Retrieval、Memory、Tools、Self-Dev、Approvals
```

### 2.3 存储

```text
PostgreSQL：从早期接入，不用 SQLite 替代主架构。
Object Store：早期使用本地 filesystem object store，接口兼容 S3/MinIO。
Qdrant：中期引入，作为派生索引，可重建。
Markdown Projection：早期只做输出投影，不做复杂双向同步。
```

## 4. 每次编码前必须读取

编码 AI 每次开始前必须读取：

```text
1. docs/current_phase.md
2. docs/编码规范.md
3. docs/project_plan_vX.md 当前阶段文件
4. final_project_plan_v7.md 中与本阶段相关章节
5. 涉及模块的源码和已有测试
```

不得只根据阶段标题猜实现。

## 5. 阶段边界与增量原则

每个阶段只实现 `project_plan_vX.md` 明确要求的内容。禁止顺手实现未来阶段功能。

示例：

```text
V2 做 Chat API + Chat Page，不做 memory。
V5 做 memory_records 和基础抽取，不做 Qdrant。
V9 做 MCP 搜索和候选提案，不安装真实 MCP。
V12 只生成 patch proposal，不修改 inactive slot。
V13 才允许修改 inactive slot。
```

增量原则：

```text
优先新增文件，不大范围删除。
优先新增 API，不破坏旧 API。
数据库迁移先 expand，不在同阶段 contract。
废弃能力先 deprecated，不立即删除。
UI 优先兼容旧后端返回。
```

## 6. 真实 LLM 与测试隔离

从 V1 开始必须有真实 LLM smoke 脚本：

```bash
python scripts/smoke/smoke_llm_ping.py
```

smoke 输出必须是结构化 JSON 或可机器检查文本，至少包含：

```json
{
  "ok": true,
  "model": "...",
  "latency_ms": 1234,
  "trace_id": "...",
  "reply_preview": "..."
}
```

普通 pytest 必须使用：

```text
FakeLLMClient
DeterministicLLMResponse
fixture-based LLM output
```

真实 LLM 调用只允许放在 `scripts/smoke/`。

## 7. 测试规范

编码 AI 默认禁止运行：

```bash
pytest
pytest tests
npm test
pnpm test --all
```

只允许运行当前阶段指定测试，例如：

```bash
pytest tests/unit/backend/test_llm_client.py -q
pytest tests/unit/backend/test_safe_delete.py::test_denies_repo_root -q
python scripts/smoke/smoke_chat_api.py
```

用户明确要求时，才可以运行更大范围测试。

测试类型：

```text
Unit Test：必须有，只测当前阶段相关模块。
Smoke Script：允许，用于真实 LLM、真实 API、真实 UI 手动验收。
Integration Test：谨慎，仅数据库/API/worker 必须跨组件时允许。
Full Regression：默认禁止。
```

## 8. 测试清理规范

测试产生的副作用必须由测试脚本、pytest fixture 或 cleanup helper 自动清理，不允许编码 AI 在测试后手动清理。

文件副作用必须使用：

```text
pytest tmp_path
隔离 sandbox directory
fixture 自动 teardown
```

数据库副作用允许方式：

```text
transaction rollback
test database
test schema
fixture teardown delete by test_run_id
```

测试写入的记录必须带：

```text
test_run_id
created_by_test = true
```

清理失败时，测试必须失败，并输出 `cleanup_report.json`。

Qdrant / Object Store：

```text
Qdrant：使用 test collection，测试结束删除 collection。
Object Store：使用 test bucket 或 test prefix，测试结束删除 prefix。
```

不可逆操作不得在真实目标执行：

```text
数据库永久写入：复制数据库或使用 test schema。
文件删除：对 tmp_path 副本执行。
forget：只对测试 memory_id 执行。
schema migration：对临时数据库或 dry run 执行。
邮件发送：fake provider / local capture inbox。
购买支付：只生成 approval_request，不执行真实下单。
```

## 9. 工具、MCP 与权限规范

每个工具必须声明：

```json
{
  "capability_id": "...",
  "definition_source": "local_builtin | generated_by_agent | remote_mcp | user_installed",
  "definition_trust_level": "trusted | semi_trusted | untrusted",
  "risk_level": "low | medium | high | critical",
  "requires_confirmation": false,
  "writes_external_world": false,
  "can_access_secret": false,
  "can_delete": false,
  "allowed_instruction_sources": ["trusted_user_command"],
  "descriptor_hash": "sha256...",
  "tool_description_is_instruction": false
}
```

工具描述只能是 metadata，不能成为系统提示词或权限来源。

MCP 能力按以下顺序放权：

```text
search metadata -> candidate proposal -> static safety review -> sandbox install -> smoke call -> user-visible activation -> runtime use
```

早期不得让 Agent 直接搜索到 MCP 后立即安装并执行。必须先进入 candidate 状态。

远端 MCP / 第三方 MCP 默认 `semi_trusted` 或 `untrusted`，必须记录：

```text
registry source
package / endpoint
version
descriptor_hash
tool list hash
requested permissions
smoke result
```

## 10. safe_delete 规范

所有删除必须走 `safe_delete(path, scope_id, mode)`。

禁止：

```text
直接 rm -rf
直接 shutil.rmtree 未经过 safe_delete
删除 /、home root、repo root、active slot root
删除未解析路径
删除 scope registry 外路径
符号链接跳出 scope 后删除
```

允许删除 AIive 自身数据，但必须归属到明确 scope：

```text
memory_cache
inactive_slot
test_artifact
old_projection
qdrant_test_collection
object_store_test_prefix
```

维护型删除优先：

```text
sleep/archive/tombstone -> semantic forget -> compaction/hard delete
```

## 11. Self-Dev 与 A/B Slot 规范

```text
active slot 运行当前版本。
inactive slot 接收复制、patch、测试。
Supervisor 管理 active_slot 指针、health check、promote、rollback。
```

Self-dev 放权顺序：

```text
patch proposal only -> apply to inactive slot -> targeted unit test -> health check -> promote -> rollback on failure
```

禁止：

```text
直接修改 active slot
跳过测试 promote
复制 data/postgres/qdrant/object_store/logs 到 slot
在一次 promote 中做破坏性 schema contract
```

## 13. 编码 AI 回复格式

编码 AI 完成阶段任务后必须输出：

```text
1. 阶段编号
2. 修改文件列表
3. 新增/修改 API
4. 数据库迁移说明
5. 运行的测试命令
6. smoke 脚本输出摘要
7. cleanup_report 路径
8. 可观测结果
9. 未实现的未来功能
10. 下一阶段交接事项
```

不得只说“已完成”。
