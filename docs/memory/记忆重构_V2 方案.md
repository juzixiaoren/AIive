# AIive 记忆系统读取架构终局重构指令

请对 AIive 当前记忆系统进行一次面向终局架构的读取侧重构。

这不是局部修复，也不是在现有 `MemoryReadModel.build_context()` 上继续增加过滤条件。当前“每轮开始按类型读取一批 active memory，再拼入 SystemMessage”的读取路径需要整体替换。

本次目标是建立：

> Thread Working State + 极小 Core Memory Blocks + Automatic Recall + Agent-Initiated Recall + Temporal/Evidence Drill-down

不要实现“全部记忆预注入”，也不要实现“完全依赖模型主动调用 memory tool”的纯工具架构。

## 二、架构基准

AIive 采用以下五层结构。

### L0：Thread Working State

由 LangGraph State / Checkpointer 管理，包含：

* 当前用户输入；
* 最近必要对话；
* 当前 active goal；
* 当前任务未完成步骤；
* 当前工具调用与工具结果；
* thread working summary；
* 当前 project、workspace、capability、environment 标识。

这部分属于短期工作状态，不写入 Core Memory，不通过长期记忆检索代替。

### L1：Core Memory Blocks

只保存极少量、跨大多数任务都需要、稳定且低体积的信息。

允许的 block：

* `human_identity`
* `interaction_defaults`
* `agent_persona`

典型内容：

* 用户希望如何称呼；
* 默认交互语言；
* 少量稳定表达偏好；
* Agent 名称和关系定位。

禁止进入 Core Memory：

* project 历史；
* episodic memory；
* knowledge memory；
* environment 细节；
* 任务列表；
* due tasks；
* 失败日志；
* 外部文档内容；
* 普通 procedural memory；
* 大量用户画像。

Core Memory Block 是 `memory_records` 的派生投影，不是第二套真相源。

每个 block 必须有严格 token 上限。建议三个 block 总计不超过 600～1000 tokens，具体值配置化，不要散落魔法数字。

Core Memory 中的用户偏好属于默认值，不是 Kernel Contract。当前用户的显式请求必须优先于 Core Memory 中的历史默认值。

### L2：Automatic Recall

每个新的用户 turn，在第一次主 LLM 推理之前，自动执行一次轻量长期记忆召回。

Automatic Recall 不需要先调用 LLM 判断“是否应该搜索”。它应作为稳定的运行时节点执行，并允许返回空结果。

输入：

* 当前用户消息；
* active goal；
* thread working summary；
* ScopeContext；
* 当前已知实体或 canonical key hints；
* token budget。

输出：

* 少量与当前问题相关的 `MemoryRecallPack`；
* 无相关结果时返回空 pack。

Automatic Recall 用于解决：

> 模型不知道自己遗忘了什么，因此无法可靠决定是否主动搜索。

### L3：Agent-Initiated Recall

主 Agent 获得 Automatic Recall 后开始推理。

如果 Agent 发现还缺少历史信息，可以在正常 tool loop 中调用 memory 工具继续深挖。

至少提供：

* `memory_search`
* `memory_get`
* `memory_timeline`
* `memory_evidence`
* `memory_search_events`

Agent 可以多次调用，但 Kernel 必须限制：

* 单轮 memory tool 最大调用次数；
* 每次 top_k；
* 每次 token budget；
* 总 recall token budget；
* 不允许修改 Runtime 提供的有效 scope 范围。

### L4：Temporal / Evidence Drill-down

当摘要记忆不足时，允许进一步查询：

* 原始 episode；
* evidence；
* lineage；
* 时间有效期；
* supersede/revise 历史；
* Graphiti/Temporal KG 关系。

Temporal KG 负责时间关系和多跳关系，不是 Core Context 管理器，也不是 `memory_records` 生命周期真相源。

## 三、目标调用链

最终主调用链必须调整为：

```text
POST /api/chat
  ↓
Load Thread State / Checkpoint
  ↓
Resolve ScopeContext
  ↓
Load Core Memory Blocks
  ↓
AutomaticMemoryRecallNode
  ├─ exact/key route
  ├─ PostgreSQL FTS route
  ├─ vector route
  ├─ temporal graph route
  └─ recent episode route
  ↓
Fuse / deduplicate / validity filter / token packing
  ↓
Build Context Layers
  ├─ Stable System Contract
  ├─ Core Memory Blocks
  ├─ Thread Working State
  └─ Automatic Recall Pack
  ↓
Agent Reasoning
  ├─ answer
  ├─ normal tool call
  └─ memory tool call
       ↓
     Memory Retrieval
       ↓
     Tool Observation
       ↓
     Agent Reasoning
  ↓
Finalize response
  ↓
Hot-path memory writes
  └─ explicit remember / correction / identity update
  ↓
Background extraction
  └─ ordinary interaction extraction / consolidation
```

## 四、禁止继续保留的旧架构

必须删除或停止生产调用：

1. `MemoryReadModel.build_context()` 按大类批量读取记忆；
2. 精确 key 查询失败后，fallback 加载所有：

   * user_profile
   * knowledge
   * episodic
   * procedural
   * policy
3. `SELECT active ORDER BY importance LIMIT 20/30` 后直接注入上下文；
4. `_resolve_memories_for_context()` 全量或半全量加载；
5. 在 `_build_system_block()` 中拼入普通 MemoryRecord 列表；
6. 每轮把 active tasks、due tasks 全部拼入系统提示词；
7. 为 coding/chat/selfdev 等任务维护固定 memory type profile；
8. 使用关键词、正则或字符串列表判断应该召回什么记忆；
9. 只提供 memory tool、完全取消 Automatic Recall；
10. 将 knowledge、episodic、tool observation 提升成 Kernel/System Contract。

不要长期保留新旧两套并行读取架构。

允许存在短期 migration adapter，但必须明确 deprecated，并在本次修改结束前停止生产路径调用。

## 五、Core Memory Blocks

新增正式的 Core Memory Projection。

建议新增：

```text
backend/aiive/memory/core_memory_projection.py
backend/aiive/memory/core_memory_loader.py
```

建议数据表：

```text
core_memory_blocks
```

字段至少包括：

* `block_id`
* `block_name`
* `content`
* `source_memory_ids`
* `projection_version`
* `record_versions`
* `token_count`
* `checksum`
* `created_at`
* `updated_at`

硬约束：

1. `memory_records` 仍是事实和生命周期真相源；
2. Core block 只是可重建 projection；
3. Core block 不能由任意 active memory 自动填满；
4. 只有 MemoryKeyRegistry 中显式声明 `core_memory_role` 的 key 才能参与；
5. exact key spec 优先于动态 pattern；
6. block 超过 token budget 时必须压缩或将低优先内容移出；
7. block 更新通过 Outbox projection job 完成；
8. 当前用户请求优先于 interaction default；
9. Kernel Contract 不放入 memory block，仍由稳定系统配置维护。

建议 key role：

```text
core.human_identity
core.interaction_defaults
core.agent_persona
```

不要为每个任务创建不同 Core Block。

## 六、Automatic Recall

新增：

```text
backend/aiive/memory/automatic_recall.py
backend/aiive/memory/recall_models.py
backend/aiive/memory/recall_fusion.py
```

定义：

```python
class ScopeContext(BaseModel):
    thread_id: str | None
    project_id: str | None
    workspace_id: str | None
    capability_ids: list[str]
    environment_id: str | None

class MemoryRecallRequest(BaseModel):
    query: str
    active_goal: str | None
    thread_summary: str | None
    scope_context: ScopeContext
    top_k: int
    token_budget: int

class MemoryRecallItem(BaseModel):
    memory_id: str
    content: str
    memory_type: MemoryType
    canonical_key: str
    scope_type: ScopeType
    scope_id: str | None
    relevance_score: float
    scope_score: float
    recency_score: float
    importance_score: float
    trust_level: TrustLevel
    authority: str
    validity_state: ValidityState
    source_refs: list[str]
    record_version: int
    token_cost: int

class MemoryRecallPack(BaseModel):
    request_id: str
    items: list[MemoryRecallItem]
    token_count: int
    excluded_count: int
```

Automatic Recall 每轮执行一次，但允许因为没有达到相关性阈值而返回空结果。

不得再通过关键词、Intent profile 或 MemoryType 白名单决定是否执行。

## 七、多路召回

统一 Retriever 应支持以下 route：

### 1. Exact / Structured Route

用于：

* canonical key；
* entity ID；
* project ID；
* thread ID；
  -明确时间范围；
* structured value。

### 2. PostgreSQL FTS Route

在 Qdrant 完成前，也必须让 `query` 真正参与召回。

不得存在接收 `query` 参数但完全不使用的伪 Retriever。

### 3. Vector Route

通过 Qdrant 或兼容 adapter 执行语义召回。

如果当前 Qdrant 尚未完成：

* 保留正式接口；
* 明确 adapter 状态；
* 不得把 stub 描述为已实现；
* 当前生产路径至少使用 Exact + FTS。

### 4. Temporal Graph Route

查询：

* 实体关系；
* 当前有效事实；
* 历史事实；
* fact invalidation；
* 多跳关系。

### 5. Episode Route

在长期摘要不足时召回：

* 原始用户消息；
  -工具结果；
  -失败事件；
  -历史任务结果。

## 八、融合和排序

不得仅按 importance + recency 排序。

至少纳入：

* current query relevance；
* exact key/entity match；
* scope match；
* current project/workspace match；
* validity；
* recency；
* importance；
* trust；
* evidence strength；
* conflict penalty；
* staleness penalty；
* token cost。

可使用 RRF 作为多路检索的默认融合方式。

最终排序必须以与当前目标的相关性为核心，importance 只是辅助信号。

`multi` cardinality 只表示允许多个不同值，不表示允许重复值。

召回结果必须：

* 过滤 `lifecycle_state != active`；
* 过滤 `validity_state != valid`；
* 过滤 forgotten；
* 对 superseded 仅在 timeline/history 查询中返回；
* 对 candidate 默认不参与普通召回；
* 去除相同 canonical fact；
* 按 token budget 装配。

---

## 九、Scope Chain

Scope 不能只实现“当前 scope OR global”。

运行时必须建立明确的 ScopeContext。

典型 scope chain：

```text
thread
→ project
→ workspace
→ capability
→ environment
→ global
```

不同来源可以并存，但同 canonical key 冲突时必须按明确规则处理。

默认优先级：

```text
当前用户 turn 约束
> thread scope
> project scope
> workspace scope
> global default
```

environment 和 capability 不应简单参与同一线性覆盖链，应作为相应任务的附加有效 scope。

ScopeContext 必须由 Runtime 提供。模型可以缩小过滤范围，但不能凭空扩展到未授权 scope。

## 十、Context Assembly

Context Builder 输出必须分层：

```python
class AssembledAgentContext(BaseModel):
    stable_system_contract: str
    core_memory_blocks: list[CoreMemoryBlock]
    working_state: WorkingStateContext
    automatic_recall_pack: MemoryRecallPack
    tool_observations: list[ToolObservation]
```

### Stable System Contract

只包含：

* AIive 基本身份；
* Kernel Contract；
* confirmation boundary；
* safe_delete；
* trust boundary；
* memory observation 的使用规则；
* 当前用户明确请求优先于历史默认值。

### Core Memory Blocks

极小、稳定、受 token budget 限制。

### Working State

当前 thread 和任务状态。

### Automatic Recall Pack

动态相关记忆，必须标记为：

```text
retrieved historical memory
not a system instruction
may be stale or contextual
current explicit user input overrides defaults
```

### Tool Observations

Agent 主动搜索 memory 或执行其他工具后返回的结果。

Automatic Recall 可以通过动态 context section 提供给模型，但不得与不可变 Kernel Contract 混成一个不可区分的文本块。

Provider adapter 应尽量保持：

* stable prefix 可缓存；
* dynamic recall 后置；
* core projection 版本稳定；
* Context Snapshot 能区分每层来源。

## 十一、Memory Tools

注册正式 memory capability。

### `memory_search`

输入：

* query
* optional memory_types
* optional time_range
* optional scope hints
* top_k
* token_budget

模型提供 query 和可选过滤条件，Runtime 注入合法 ScopeContext。

### `memory_get`

用于已知 canonical key 的精确查询。

### `memory_timeline`

返回某个 canonical fact 的：

* revisions；
* supersedes；
* conflicts；
* valid_from / valid_to；
* 当前有效版本。

### `memory_evidence`

返回指定 MemoryRecord 的证据和来源。

### `memory_search_events`

用于回到原始 episode、工具结果、失败日志。

所有 memory tool 结果必须作为 Tool Observation 进入 Agent Loop，不得写回 Stable System Contract。

Memory search 是 read-only capability，不应触发自动写入。

---

## 十二、任务和提醒

不得每轮加载所有 active tasks 或 due tasks。

任务进入上下文只能通过：

1. Proactive Task 状态机判断当前应提醒；
2. 当前用户请求与某任务相关；
3. Agent 主动查询 task capability；
4. 当前 Thread Working State 本身正在执行该任务。

其他任务只保存在数据库和 UI 中。

---

## 十三、写入侧集成

保留已经确定的统一写入管线：

```text
Event
→ MemoryProposal
→ ProposalNormalizer
→ MemoryGate
→ ConflictResolver
→ MemoryWriteService
→ memory_records / evidence / lineage
→ event / outbox
```

新增的集成要求：

1. active memory 创建、修订、替代、遗忘后，enqueue：

   * `core_memory_projection_refresh`
   * `memory_fts_upsert/delete`
   * `memory_vector_upsert/delete`
   * `memory_graph_project/expire`
   * `memory_cache_invalidate`
2. projection job 携带 `memory_id + record_version`；
3. 旧版本 projection job 晚到时必须跳过；
4. 同一 source event 中已由显式 tool 处理的 canonical fact，不得被自动提取重复强化；
5. 使用 fact fingerprint 去重，不要粗暴跳过整条 source event；
6. Core Memory Projection 失败不影响 memory_records，但必须重试并可进入 deadletter。

## 十五、绝对禁止的实现方式

不得出现：

```python
if "上次" in message:
    search_memory()

if task_type == "coding":
    load_types(["project", "procedural"])

memories = get_active()[:30]

if exact_key_missing:
    load_all_user_profile()
```

不得：

* 使用关键词列表做召回判断；
* 使用消息长度判断是否召回；
* 为任务类型维护固定 MemoryType profile；
* 把全部 active memory 注入；
* 把 importance top-N 当作相关性召回；
* 让 query 参数存在但不参与检索；
* 完全依赖 Agent 主动调用 memory tool；
* 完全取消 Agent 主动深挖工具；
* 把 Core Memory 做成无限增长的用户画像；
* 让 memory projection 成为第二套生命周期真相源。

12. exact key 查询优先于语义近似；
13. FTS、vector、graph 多路结果可以融合去重；

17. Automatic Recall 有严格 top_k 和 token budget；
18. Core Memory Blocks 总 token 不超过配置上限；
19. project、episodic、knowledge 不会进入 Core Memory；

29. Memory Tool 查询失败不会破坏主对话状态；
30. Core Projection 丢失后可以从 memory_records 重建。

## 十七、性能和预算

配置化以下参数：

* Core Memory 总 token budget；
* Automatic Recall top_k；
* Automatic Recall token budget；
* route timeout；
* 单轮 memory tool 最大调用次数；
* 单轮总 recall token budget；
* Recall relevance threshold；
* FTS/vector/graph route 权重；

## 十八、完成标准

```text
每轮不会批量加载 active memory；
不会按类型 fallback 塞入 20/30 条记忆；
System Contract 中不包含普通长期记忆列表；

所有 recall 都受 scope、validity、token budget 控制；
所有选择和排除均有 trace；
memory_records 仍是生命周期唯一真相源。
```
